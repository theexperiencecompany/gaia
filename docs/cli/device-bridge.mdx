Let GAIA run commands on your machine and use its local MCP servers, over one outbound tunnel.

Once a machine is connected, GAIA runs shell commands on it with the `run_on_device` tool and reads or writes files the device's user account can access. The bridge opens no inbound ports.

You can pair a machine with GAIA Cloud or your own instance. It does not require self-hosting.

## Pick a way to connect

| Option                                                          | Best for                                              |
| --------------------------------------------------------------- | ----------------------------------------------------- |
| [Desktop app](#connect-with-the-desktop-app-macos-and-linux)    | The computer you're on (macOS, Linux). No code needed. |
| [`gaia` CLI](#connect-with-the-cli)                             | Servers, Windows (WSL2), and scripts.                 |

The desktop app and CLI are separate devices. Each appears in **Settings > Devices**, and revoking one leaves the other online.

## Connect with the desktop app (macOS and Linux)

<Steps>
  <Step title="Open Devices">
    In the desktop app, go to **Settings > Devices**. The **This computer** card is at the top.
  </Step>
  <Step title="Enable it">
    Click **Enable on this computer**. The status chip switches to **Online**.
  </Step>
  <Step title="Add MCP servers (optional)">
    Use **Add server** on the same card. The toggle pauses or resumes the tunnel.
  </Step>
</Steps>

The menu-bar item shows the status (online, paused, or not connected). From it you can connect, pause, open the app, or quit. Turn on **Launch at login** there to stay online across restarts.

<Note>
  On macOS, protected folders like Downloads, Desktop, and Documents need **Full Disk Access** for **GAIA.app**. Grant it in **System Settings > Privacy & Security > Full Disk Access**. Linux needs nothing extra.
</Note>

## Connect with the CLI

Needs macOS, Linux, or Windows (WSL2 recommended), and Node.js 20 or later.

<Steps>
  <Step title="Install the CLI">
    <Snippet file="cli-install.mdx" />
  </Step>
  <Step title="Pair this machine">
    ```bash
    gaia bridge login
    ```
    The CLI prints a code and a link, then waits.
  </Step>
  <Step title="Approve the code">
    Paste the code into a GAIA chat and click approve, or enter it in **Settings > Devices** (`/settings/devices/approve`).
  </Step>
  <Step title="Go online">
    ```bash
    gaia bridge up
    ```
    This runs the tunnel as a background daemon. The device stays online after you close the shell.
  </Step>
</Steps>

To stop, run `gaia bridge down`. GAIA sees the device as offline while the tunnel is down.

### Add a local MCP server

```bash
gaia bridge add
```

The wizard walks you through pairing first if needed. It connects either kind of server:

<AccordionGroup>
  <Accordion title="A command that starts a server (stdio)">
    Give it the launch command, like `npx -y @modelcontextprotocol/server-everything`, `uvx some-server`, or `docker run -i --rm my/image`. The wizard asks for any env vars the server needs, then starts it and lists its tools before saving.
  </Accordion>
  <Accordion title="A server already running at a local URL">
    Give it a loopback URL like `http://localhost:3000/mcp` (`localhost`, `127.0.0.1`, or `::1`). You can add request headers such as `Authorization`.
  </Accordion>
</AccordionGroup>

Secrets you enter stay on your machine. After saving, the wizard registers the server with GAIA and offers to start the tunnel.

<Note>
  On macOS, the CLI's protected-folder access comes from the terminal that runs `gaia bridge up`. Grant **Full Disk Access** to that terminal.
</Note>

## Commands

| Command                | What it does                                             |
| ---------------------- | -------------------------------------------------------- |
| `gaia bridge login`    | Pair this machine. `--name <name>` sets the device name; `--api <url>` targets a specific GAIA API. |
| `gaia bridge add`      | Wizard to connect a local MCP server                     |
| `gaia bridge up`       | Start the tunnel in the background (device online)       |
| `gaia bridge down`     | Stop the tunnel (device offline)                         |
| `gaia bridge ls`       | Show pairing status and configured servers               |
| `gaia bridge rm <key>` | Remove a server. Get the key from `gaia bridge ls`.      |
| `gaia bridge logout`   | Forget local credentials on this machine                 |

`gaia bridge logout` only clears local credentials. To fully revoke a device, remove it in **Settings > Devices**.

## Security

- **Outbound only.** No inbound ports, no port forwarding.
- **Access follows the device.** GAIA can reach files the device's user account can, and only while the tunnel is up.
- **Secrets stay local.** Env vars and headers are not uploaded.
- **Revoke anytime** in **Settings > Devices**.
