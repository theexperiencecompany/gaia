Run the tests for the code you changed, not the whole suite. The full suites are large and CI runs them on every pull request. All commands run from the repository root.

## What to run for your change

| You changed | Run |
| --- | --- |
| API code (`apps/api`) | `mise test:one tests/unit/path/test_x.py [more files]`, paths relative to `apps/api/` |
| Web app (`apps/web`) | `nx test web` |
| A user-facing web flow | `mise e2e:web`, with `mise dev --sim` running in another terminal |
| Bots (`apps/bots`) | `mise test:bots` |
| The `gaia` CLI (`packages/cli`) | `mise test:cli` |
| Shared TypeScript (`libs/shared/ts`) | `nx test shared-typescript` |
| Mobile or desktop | `nx test mobile`, `nx test desktop` |

**Why `mise test:one` and not plain `pytest`.** It runs pytest exactly as CI does: the same markers, the same default filter and the same timeout, but on one process. Running the full API suite starts several worker processes that each load the whole app, which can exhaust a laptop's memory.

TypeScript tests use [Vitest](https://vitest.dev). Web end-to-end tests use [Playwright](https://playwright.dev) and drive a real browser against your running stack. Set `E2E_SIM=1` to include the scripted-chat test.

## The API test tiers

API tests live in `apps/api/tests/`, one folder per **tier**. A tier is a level of realism: a unit test replaces everything around the code with fakes, a real-infra test talks to real databases.

| Tier | Folder | Needs | Write one when |
| --- | --- | --- | --- |
| Unit | `tests/unit/` (mirrors `app/`) | Nothing | You add or change a function, service or endpoint |
| Integration | `tests/integration/` | Nothing. Real code, fake databases | Several components have to work together |
| End to end | `tests/e2e/` | Nothing. The real agent graphs with a fake model | A user journey through the agents |
| Stress | `tests/stress/` | Nothing | Retries, races or idempotency |
| Meta | `tests/meta/` | Nothing | Architecture rules, such as which module may import which |
| Real infra | `tests/integration/real/` | Docker and `USE_REAL_SERVICES=1` | The behavior only shows against real Postgres, Redis or Mongo |
| Contracts | `tests/contracts/` | Real Mongo and Redis | You change a repository (database access) class |
| Live | `tests/composio/`, `tests/model_onboarding/` | Real credentials, costs money | Rarely. Excluded by default |

By default pytest deselects the tests marked `composio`, `model_onboarding` and `schemathesis`. Real-infra and contract tests skip themselves unless `USE_REAL_SERVICES=1` is set.

Broader runs, when you need them:

| Command | Runs |
| --- | --- |
| `mise test:python:unit` | Every unit test |
| `mise test:python:hermetic` | Every tier that needs no Docker and no network |
| `mise test:python:real` | The real-infra and contract tiers, against the Docker services |
| `mise test:python` | The full suite with real services, inside [Dagger](https://dagger.io) containers, as CI runs it |

## Writing a test

The full conventions, including the fixture catalog, are in `apps/api/tests/CLAUDE.md`. The rules that matter most:

1. **It must be able to fail.** Delete the line of product code the test is about. If the test still passes, it tests nothing.
2. **Assert behavior, not implementation.** Check the response, the stored data or the returned value, not which internal function was called.
3. **Mock the edges, never the code under test.** Fake the database, HTTP client or model. Never patch the function you are testing.
4. **Cover the failure path.** Test what happens when a dependency fails, not only the happy path.
5. **Never assert on text an AI model wrote.** Assert on structure, tool calls and state.
6. **Fixing a bug? Write the test first and watch it fail.** A test you never saw fail proves nothing. Mark it `@pytest.mark.regression`, and CI checks that it really fails without your fix.

Search the shared fixtures before writing your own: `tests/conftest.py` (an authenticated `client`, `fake_user`, `fake_redis`), `tests/factories.py` (`make_user`, `make_conversation`) and `tests/helpers.py` (`create_fake_llm`). To start a new file, copy a scaffold from `tests/_template/`.

Tests never see your real keys: at the start of a run, the suite blanks every environment variable that looks like a credential, so a test can't call a paid API by accident.
