All of GAIA's development commands are [mise](https://mise.jdx.dev) tasks. Run them from the repository root. `mise tasks` prints the full list with descriptions, and is always up to date, so treat it as the source of truth if this page and your checkout ever disagree.

`mise <task>` and `mise run <task>` are the same thing. The longer form also works when a task name clashes with a mise command.

## Set up

| Command | Does |
| --- | --- |
| `mise bootstrap` | Everything for a fresh machine: git, curl and Docker, the toolchain, then env files, dependencies, voice models and the databases |
| `mise run bootstrap` | The same without the machine part: env files, dependencies, voice models, the databases |
| `mise run setup:env` | Copy any missing `.env` file from its `.env.example`. Never overwrites |
| `mise run setup:deps` | Install the JavaScript and Python dependencies |
| `mise run setup:voice-agent` | Install the voice agent and download its speech models |
| `mise run setup:mobile`, `mise run setup:desktop` | Install the mobile or desktop app's dependencies |
| `mise run pre-commit:install` | Install the commit and push hooks |

## Run

| Command | Starts |
| --- | --- |
| `mise dev --agent` | API and web, signed in as the development user |
| `mise dev --sim` | The same, with scripted AI replies |
| `mise dev` | API and web, with the real sign-in flow |
| `mise dev:api`, `mise dev:web` | One of the two |
| `mise dev:arq` | API, web and the ARQ background worker |
| `mise dev:bots` | All five bots |
| `mise dev:full` | API, web, worker, voice agent and all bots |
| `mise dev:mobile` | API and the Expo dev server |
| `mise dev:vm` | API in a container (for JuiceFS features) and web |
| `mise seed` | Create the development user and sample data in a running API |
| `mise infisical -- <task>` | Any task with the team's secrets injected (team members) |
| `mise run wt:env` | Give this checkout its own ports |

[Run GAIA locally](/developers/running-locally) explains when to use each.

## Check

| Command | Does |
| --- | --- |
| `mise run lint` | Lint every Nx project (Biome for TypeScript, Ruff for the API) |
| `mise run lint:fix` | Fix lint findings, format, and sort imports |
| `mise run lint:py` | Lint and format-check every Python file in the repository, exactly as CI does |
| `mise run lint:py:fix` | The same, fixing what it can |
| `mise run type-check` | Type-check every project (TypeScript and mypy) |
| `mise run format` | Fix whitespace and indentation only. Use `lint:fix` to also sort imports |
| `mise run format:check` | Check formatting without changing files |
| `mise ci:local --only <lane>` | Run one CI check locally, at CI's pinned versions. `--list` prints the checks |
| `mise ci:remote` | Explain why the current branch's pull request is red |
| `mise run api:types` | Regenerate the TypeScript API types after changing an API route or model |

Add `:affected` to `lint`, `type-check`, `format`, `build` or `test` to run it only on the projects your branch changed, for example `mise run lint:affected`.

## Test

| Command | Runs |
| --- | --- |
| `mise test:one <file> [more]` | One or more API test files, as CI runs them. Paths are relative to `apps/api/` |
| `mise test:python:unit` | Every API unit test |
| `mise test:python:hermetic` | Every API test that needs no Docker and no network |
| `mise test:python:real` | The API tests that need the Docker services |
| `mise test:python` | The full API suite in Dagger containers, as CI runs it |
| `mise test:bots` | The bot tests |
| `mise test:cli` | The `gaia` CLI tests |
| `mise e2e:web` | Web end-to-end tests against a running `mise dev --sim` |
| `nx test <project>` | One project's tests, for example `nx test web` |

`mise test` runs the `test` target of every Nx project, the full API suite included. It is slow and memory-hungry on a laptop, so prefer the targeted commands above. [Testing](/developers/testing) has the details.

## Build and clean

| Command | Does |
| --- | --- |
| `mise run build` | Build every project |
| `mise run clean` | Remove every project's build output |
| `mise run clean:nx` | Reset the Nx cache |
| `mise run graph` | Open the Nx project graph in the browser |

## Tasks inside an app

Each app also has its own `mise.toml` with tasks specific to it. Run them from the root with `//`, or from inside the app folder without it:

```bash
mise //apps/api:mypy     # from the root
cd apps/api && mise mypy # from inside the app
```

| App | Useful tasks |
| --- | --- |
| `apps/api` | `worker` (ARQ worker), `mypy`, `bandit` (security scan), `pip:audit`, `secrets` (find committed secrets), `schema` (API schema tests), `seed:workflows` |
| `apps/web` | `analyze` (bundle size), `knip` (unused files and exports), `clean:cache` |
| `apps/mobile` | `android`, `ios`, `dev:clear` (clear the Metro cache), `prebuild`, `build:dev`, `build:preview`, `build:prod`, `submit` (EAS cloud builds and store submission) |
| `apps/desktop` | `dev` (API, web and Electron), `dist` (installer for this platform), `dist:mac`, `dist:win`, `dist:linux` |

`cd apps/<app> && mise tasks` lists an app's tasks.
