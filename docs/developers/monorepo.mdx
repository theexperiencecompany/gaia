## The API (`apps/api`)

```
apps/api/
├── app/
│   ├── main.py           Entry point. Builds the app through core/app_factory.py
│   ├── worker.py         ARQ worker settings (the background job runner)
│   ├── api/v1/
│   │   ├── routes.py     Mounts every router under /api/v1
│   │   ├── endpoints/    One module per route group
│   │   ├── middleware/   Auth, logging, rate limits
│   │   └── dependencies/ FastAPI dependencies, such as the current user
│   ├── agents/           The AI agents: graphs, tools, prompts, skills, memory hooks
│   ├── services/         Business logic, *_service.py
│   ├── models/           Pydantic models, *_models.py
│   ├── db/               MongoDB, PostgreSQL, Redis, ChromaDB and RabbitMQ clients, plus repositories/
│   ├── memory/           The memory engine
│   ├── workers/tasks/    The ARQ job functions
│   ├── config/           Settings (settings.py) and integration definitions (oauth_config.py)
│   └── constants/        Named constants, grouped by domain
├── tests/                See Testing
└── scripts/              One-off operational scripts
```

An endpoint stays thin: it validates input and calls a service, and the service does the work through a repository in `db/repositories/`. `apps/api/CLAUDE.md` is the full contract.

## The web app (`apps/web`)

```
apps/web/src/
├── app/[locale]/         Next.js routes, one folder per URL, under a language prefix
│   ├── (landing)/        Marketing pages, login and signup
│   ├── (main)/           The signed-in app: /c (chat), /todos, /calendar, /settings, ...
│   └── (desktop)/        Screens only the desktop app uses
├── features/<feature>/   Everything one feature owns: components, hooks, stores, api/
├── components/           UI shared across features
├── stores/               Global Zustand stores
├── lib/                  Cross-cutting helpers (api client, analytics, ...)
└── types/                Shared TypeScript types
```

Folders in parentheses, such as `(main)`, are Next.js **route groups**: they share a layout without adding to the URL. API request and response types are generated from the API's OpenAPI schema into `@gaia/shared/api/generated`, never written by hand. `apps/web/CLAUDE.md` covers state, components and styling.

## Shared libraries

| Library | Imported as | Holds |
| --- | --- | --- |
| `libs/shared/py` | `shared.py` (the `gaia-shared` package, defined in `libs/pyproject.toml`) | Logging and wide events, settings helpers, secrets loading, the analytics catalog |
| `libs/shared/ts` | `@gaia/shared` | The bot framework, the generated API and analytics types, chat and tool helpers, icons |
| `libs/wake-word` | `@gaia/wake-word` | On-device "Hey GAIA" detection |

The Python apps get `gaia-shared` through the uv workspace, so `uv sync` installs it. Shared code goes here rather than being copied between apps.

## Packages

`packages/cli` is the `gaia` command, published to npm as `@heygaia/cli`. [CLI internals](/developers/cli-internals) covers trying and releasing it. `packages/gaia-ui` holds only a README: the `@heygaia/ui` component kit lives in [its own repository](https://github.com/theexperiencecompany/gaia-ui).

## How Nx runs everything

Every app, library and package is an Nx **project** with a `project.json` that declares its **targets**: `dev`, `build`, `lint`, `type-check`, `test` and so on. The root `mise` tasks call Nx, and Nx runs the targets in dependency order, in parallel, and caches the result so unchanged projects are skipped.

```bash
nx show projects              # every project name
nx show project api           # one project's targets
nx dev api                    # run one target of one project
nx run-many -t lint           # run a target across every project
nx affected -t test           # only the projects your branch changed
```

Project names mostly match the folder (`api`, `web`, `mobile`, `desktop`, `voice-agent`, `cli`, `docs`, `wake-word`), with a few exceptions: the bots are `bot-discord`, `bot-slack`, `bot-telegram`, `bot-whatsapp` and `bot-imessage`, the bot simulator is `bot-harness`, the shared bot tests are `bots-e2e`, the shared libraries are `shared-python` and `shared-typescript`, and the Docker services are `docker`.

mise can also run a task defined in an app's own `mise.toml` from the root, with `//` syntax: `mise //apps/api:mypy` runs `mypy` from `apps/api/mise.toml`. [Commands](/developers/commands) lists them.
