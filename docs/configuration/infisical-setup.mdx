Load the team's shared secrets with Infisical. Most contributors don't need it.

<Note>
  Infisical is **optional**. Self-hosters and contributors should use plain `.env` files, see [Environment Variables](/configuration/environment-variables). It is only required when `ENV=production`.
</Note>

## Team members: run tasks with your login

<Steps>
  <Step title="Install the CLI">
    ```bash
    brew install infisical/get-cli/infisical
    ```

    Other platforms: [Infisical CLI docs](https://infisical.com/docs/cli/overview).
  </Step>

  <Step title="Log in">
    ```bash
    infisical login
    ```

    Use `infisical login -i` inside containers or WSL2.
  </Step>

  <Step title="Run a task">
    ```bash
    mise infisical dev
    ```

    This runs the task with every secret from the `development` environment injected. Pass flags after `--`:

    ```bash
    mise infisical -- dev --agent
    ```
  </Step>
</Steps>

`.infisical.json` in the repo names the project. It holds no secrets.

## How the apps load secrets

At startup the API, bots, and voice agent fetch secrets for your `ENV` and inject each one **only if it isn't already set**. Local variables always win. The web app never calls Infisical.

If no Infisical variables are set, development continues with your local `.env`. Production refuses to start. Self-host (`ENV=selfhost`) never contacts Infisical.

<Warning>
  When `ENV` is unset, the Python apps (API, voice agent) default to `production` and refuse to boot without Infisical. Copy `apps/api/.env.example`, which sets `ENV=development`. The bots default to `development`.
</Warning>

<Accordion title="Infra URLs and local tweaks">
  The `development` environment stores **localhost** URLs, because `mise dev` runs the API on the host and reaches Docker through published ports. Don't put Docker hostnames there.

  For a local tweak, use [personal overrides](https://infisical.com/docs/documentation/platform/secret-overrides) in the dashboard instead of editing `.env`. The CLI caches secrets, so `infisical run` also works offline.
</Accordion>

<Accordion title="Use your own Infisical project (headless)">
  Create a machine identity with Universal Auth, grant it read access, then set these in the local environment. They can't be stored in Infisical itself.

  ```bash
  INFISICAL_PROJECT_ID=your-project-id
  INFISICAL_MACHINE_IDENTITY_CLIENT_ID=your-client-id
  INFISICAL_MACHINE_IDENTITY_CLIENT_SECRET=your-client-secret
  ENV=development
  ```

  Set all three or none. A partial set warns in development and fails the boot in production.
</Accordion>

<Accordion title="Production (Docker Swarm)">
  Production uses one machine identity shared by every service. The compose file lives in the private `gaia-infra` repo. Store the credentials as Swarm secrets:

  ```bash
  printf '%s' '<client-id>'     | docker secret create gaia_infisical_machine_identity_client_id -
  printf '%s' '<client-secret>' | docker secret create gaia_infisical_machine_identity_client_secret -
  printf '%s' '<project-id>'    | docker secret create gaia_infisical_project_id -
  ```

  `scripts/docker-entrypoint.sh` reads them from `/run/secrets/` before starting the app.

  To limit the blast radius, create one identity per service and map each onto the canonical names with Compose's long syntax. Only the compose file changes.

  ```yaml
  secrets:
    - source: gaia_api_infisical_client_id
      target: gaia_infisical_machine_identity_client_id
    - source: gaia_api_infisical_client_secret
      target: gaia_infisical_machine_identity_client_secret
  ```
</Accordion>

<Accordion title="Why the web app skips Infisical">
  Its environment is the `NEXT_PUBLIC_*` variables in `apps/web/.env.example`, which are compiled into the browser bundle and are public anyway. The one server-only secret, `BLOG_BEARER_TOKEN`, goes in Cloudflare:

  ```bash
  wrangler secret put BLOG_BEARER_TOKEN
  ```

  Under `mise infisical dev`, Next still sees Infisical values because the CLI injects them before Next starts. Don't bootstrap Infisical into the Worker: that ships a project-wide credential to the edge.
</Accordion>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Infisical is required in production">
    `ENV` resolved to `production` without Infisical credentials. Provide the machine identity credentials, or set `ENV=development`.
  </Accordion>

  <Accordion title="Incomplete Infisical config: missing ...">
    Only some of the three `INFISICAL_*` variables are set. Set all three or remove all three.
  </Accordion>

  <Accordion title="Authentication failed or secrets not loading">
    Check the client ID and secret, that the identity is enabled with read access, and that the environment slug matches `ENV`.
  </Accordion>

  <Accordion title="A value isn't applied">
    A local variable with the same name is set. Unset it in your shell and `.env` files.
  </Accordion>
</AccordionGroup>

Startup logs show connection, fetch, and injection timing, plus any Infisical error.
