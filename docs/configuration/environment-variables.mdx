Look up what each setting in an `.env` file does.

<Tip>
  **Self-hosting?** You don't need this page to get started. `gaia up` writes a working configuration and generates every secret. See [CLI setup](/self-hosting/cli-setup). Add AI and tool keys in **Settings → Providers & Tools**, no file editing needed.
</Tip>

Most variables are optional. A missing key turns off one feature, and the app still starts.

## How settings load

Settings live in `apps/api/app/config/settings.py` and run in one of three modes:

| Mode | What is required |
| --- | --- |
| Development | Little. Missing keys just disable features |
| Self-host (`ENV=selfhost`) | Database addresses and machine secrets. Provider keys are set at runtime |
| Production | Database addresses and secrets. A missing integration key turns that integration off with a warning, and GAIA still boots |

## Manual setup (contributors)

<Steps>
  <Step title="Copy the example files">
    ```bash
    cp apps/api/.env.example apps/api/.env
    cp apps/web/.env.example apps/web/.env
    ```
  </Step>
  <Step title="Set the minimum">
    In `apps/api/.env`:

    ```bash
    ENV=development
    MONGO_DB=mongodb://mongo:27017/gaia
    REDIS_URL=redis://redis:6379
    AUTH_MODE=local
    ```

    `AUTH_MODE=local` gives email-and-password sign-in with no outside service. For WorkOS, use `AUTH_MODE=workos` and set the [WorkOS variables](#authentication-oauth).
  </Step>
  <Step title="Start">
    ```bash
    mise dev
    ```
  </Step>
</Steps>

## API Environment Variables

<Note>
  On a self-hosted instance, the provider and tool keys (AI providers, search, Firecrawl, OpenWeather, LlamaParse, GitHub, Cloudinary, Google OAuth, Composio, Resend, E2B) can be set in **Settings → Providers & Tools** instead, where they are stored encrypted. The environment variable is used when nothing is saved there.
</Note>

### Always Required

These are required in **every** mode:

| Variable                 | Description                               |
| ------------------------ | ----------------------------------------- |
| `ENV`                    | `development`, `production`, or `selfhost` |
| `MONGO_DB`               | MongoDB connection string                 |
| `REDIS_URL`              | Redis connection string                   |

In production and self-host, these are also required:

| Variable                    | Description                                                          |
| --------------------------- | -------------------------------------------------------------------- |
| `POSTGRES_URL`              | PostgreSQL connection (optional in development)                      |
| `RABBITMQ_URL`              | RabbitMQ connection (optional in development)                        |
| `AGENT_SECRET`              | Voice agent authentication secret                                    |
| `BOT_SESSION_TOKEN_SECRET`  | Secret for bot session tokens (min 32 chars)                          |
| `EMAIL_UNSUBSCRIBE_SECRET`  | Secret for signing unsubscribe links                                 |

### Instance & Auth Mode

| Variable           | Default    | Description                                                                                     |
| ------------------ | ---------- | ----------------------------------------------------------------------------------------------- |
| `AUTH_MODE`        | `workos`   | `local` (email + password sign-in) or `workos` (AuthKit hosted UI). Self-host uses `local`; production refuses it. |
| `INSTANCE_SECRET`  | generated  | Signs local sessions and derives the key that encrypts stored provider credentials. `gaia up` writes a random one into `.env` on a fresh install, which keeps the key out of the database. If it is unset, a secret is generated on first boot and stored in the database next to the credentials it encrypts, so anyone with a database dump can decrypt them. Never change it once credentials are stored. |
| `OLLAMA_BASE_URL`  | unset | Ollama endpoint as seen by the backend; unset means no Ollama lane. Inside Docker use `http://host.docker.internal:11434`; native runs use `localhost`. |

### Environment & Deployment

| Variable                    | Default                  | Description                   |
| --------------------------- | ------------------------ | ----------------------------- |
| `HOST`                      | `https://api.heygaia.io` | API host URL                  |
| `FRONTEND_URL`              | `https://heygaia.io`     | Frontend app URL              |
| `ENABLE_PROFILING`          | `false`                  | Enable performance profiling  |
| `SHOW_MISSING_KEY_WARNINGS` | `true`                   | Log warnings for missing keys |
| `BLOB_STORE`                | per deployment           | Where uploaded and generated files live: `local` (self-host) or `cloudinary`. Never `local` in production |
| `LOCAL_FILE_STORAGE_PATH`   | `/var/lib/gaia/files`    | Folder for files under `BLOB_STORE=local`; the self-host compose mounts a volume here |
| `LOOPBACK_HOST_ALIAS`       | unset                    | Hostname that reaches the host from inside the container (`host.docker.internal` in the self-host compose), so a custom MCP server added as `localhost` still works |

### Authentication & OAuth

| Variable                    | Required  | Description                          |
| --------------------------- | --------- | ------------------------------------ |
| `WORKOS_API_KEY`            | Only when `AUTH_MODE=workos` | WorkOS API key for authentication |
| `WORKOS_CLIENT_ID`          | Only when `AUTH_MODE=workos` | WorkOS client ID                 |
| `WORKOS_COOKIE_PASSWORD`    | Only when `AUTH_MODE=workos` | Secret for session cookies (min 32 chars) |
| `GOOGLE_CLIENT_ID`          | Prod only | Google OAuth client ID               |
| `GOOGLE_CLIENT_SECRET`      | Prod only | Google OAuth client secret           |
| `DISCORD_OAUTH_CLIENT_ID`   | Optional  | Discord OAuth app client ID          |
| `DISCORD_OAUTH_CLIENT_SECRET` | Optional | Discord OAuth app client secret     |
| `SLACK_OAUTH_CLIENT_ID`     | Optional  | Slack OAuth app client ID            |
| `SLACK_OAUTH_CLIENT_SECRET` | Optional  | Slack OAuth app client secret        |

<Note>
  `AUTH_MODE` selects the sign-in method: `workos` routes users through
  WorkOS's AuthKit hosted UI, while `local` enables first-party email +
  password accounts (the self-host default, also usable in development so
  contributors need no WorkOS account — the first account created becomes the
  instance admin, and others join by invite link from Settings → Members). The
  three `WORKOS_*`
  variables are validated and required only when `AUTH_MODE=workos`.
</Note>

<Note>
  Computed OAuth callback URLs are generated automatically: -
  `WORKOS_REDIRECT_URI` → `{HOST}/api/v1/oauth/workos/callback` -
  `GOOGLE_CALLBACK_URL` → `{HOST}/api/v1/oauth/google/callback` -
  `COMPOSIO_REDIRECT_URI` → `{HOST}/api/v1/oauth/composio/callback` -
  `DISCORD_OAUTH_REDIRECT_URI` → `{HOST}/api/v1/platform-auth/discord/callback` -
  `SLACK_OAUTH_REDIRECT_URI` → `{HOST}/api/v1/platform-auth/slack/callback`
</Note>

<Note>
  `DISCORD_OAUTH_CLIENT_ID` and `SLACK_OAUTH_CLIENT_ID` are optional, without them, users must link their accounts using the `/auth` bot command instead of the web UI. See [Discord Bot](/bots/discord) and [Slack Bot](/bots/slack) for setup instructions.
</Note>

### Memory & Context

Memory runs locally on PostgreSQL, ChromaDB and a local embedding model. No keys are needed, and the defaults work.

<Accordion title="Tuning variables">
  | Variable | Description |
  | --- | --- |
  | `GAIA_EMBEDDING_MODEL` | Embedding model name (default `mixedbread-ai/mxbai-embed-large-v1`) |
  | `GAIA_EMBEDDING_DIM` | Embedding vector dimension (default `1024`) |
  | `MEMORY_EMBEDDING_SIDECAR_URL` | URL of a shared embedding sidecar; loads the model in-process when unset |
  | `MEMORY_EMBEDDING_SIDECAR_CONCURRENCY` | Max in-flight sidecar inferences (default `cores / MEMORY_ONNX_THREADS`) |
  | `MEMORY_ONNX_THREADS` | ONNX intra-op threads per inference (default `4`) |
  | `MEMORY_SIDECAR_MAX_BATCH_TEXTS` | Max texts per embedding forward pass / per HTTP call (default `16`) |
  | `MEMORY_SIDECAR_MAX_BATCH_CHARS` | Max total characters per embed/rerank HTTP chunk (default `64000`) |
  | `MEMORY_SIDECAR_MAX_TEXT_CHARS` | Hard cap on a single text; larger inputs are rejected with `413` (default `65000`) |
  | `MEMORY_SIDECAR_SLOT_WAIT_SECONDS` | How long a request waits for an inference slot before `503` (default `20`) |
  | `MEMORY_SIDECAR_RETRIES` | Retries for transient sidecar failures (`429`/`503`/connection errors) before failing (default `2`) |
  | `MEMORY_SIDECAR_RETRY_MAX_WAIT_SECONDS` | Backoff between sidecar retries in seconds (default `5`) |
  | `MEMORY_MODEL_CACHE_DIR` | Persistent cache for fastembed model weights (~1.85GB, avoids re-download) |
  | `GAIA_CHROMA_COLLECTION_SUFFIX` | Suffix appended to ChromaDB collection names (for isolating environments) |
</Accordion>

## Full Example

<Accordion title="Complete apps/api/.env example (development, local auth)">
```bash
# Environment
ENV=development
HOST=http://localhost:8000
FRONTEND_URL=http://localhost:3000

# Databases (Docker defaults)

MONGO_DB=mongodb://mongo:27017/gaia
REDIS_URL=redis://redis:6379
POSTGRES_URL=postgresql://postgres:postgres@postgres:5432/langgraph
CHROMADB_HOST=chromadb
CHROMADB_PORT=8000
RABBITMQ_URL=amqp://guest:guest@rabbitmq:5672/

# Auth — email + password, no external provider needed

AUTH_MODE=local

# To use WorkOS instead, set AUTH_MODE=workos and add:
# WORKOS_API_KEY=sk_test_xxxx
# WORKOS_CLIENT_ID=client_xxxx
# WORKOS_COOKIE_PASSWORD=your-32-character-random-secret

# Google OAuth (optional in dev)

GOOGLE_CLIENT_ID=xxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxx

# AI (add what you need — or configure in Settings → Providers & Tools)

OPENAI_API_KEY=sk-xxxx
GOOGLE_API_KEY=AIza-xxxx

# Search & Tools

TAVILY_API_KEY=tvly-xxxx
FIRECRAWL_API_KEY=fc-xxxx

# Media

CLOUDINARY_CLOUD_NAME=your-cloud
CLOUDINARY_API_KEY=xxxx
CLOUDINARY_API_SECRET=xxxx

# Monitoring

SENTRY_DSN=https://xxxx@sentry.io/xxxx
POSTHOG_PROJECT_TOKEN=phc_xxxx

```
</Accordion>

<Accordion title="Minimal apps/api/.env example (self-host)">
`gaia up` generates this for you — shown here for reference:

```bash
ENV=selfhost
AUTH_MODE=local

MONGO_DB=mongodb://mongo:27017/gaia
REDIS_URL=redis://redis:6379
POSTGRES_URL=postgresql://postgres:postgres@postgres:5432/langgraph
CHROMADB_HOST=chromadb
CHROMADB_PORT=8000 # container port (8080 is host-mapped only)
RABBITMQ_URL=amqp://guest:guest@rabbitmq:5672/

# Generated per machine by gaia up — never commit these anywhere
AGENT_SECRET=<generated>
BOT_SESSION_TOKEN_SECRET=<generated>
EMAIL_UNSUBSCRIBE_SECRET=<generated>
```

Everything else is optional. AI provider keys are added at runtime in
**Settings → Providers & Tools**; Infisical is never contacted.
</Accordion>

## Generate the file for you

`gaia up` writes a complete self-host configuration. For a source checkout, run the interactive wizard:

```bash
gaia init
```

It reads the config schema and `.env.example`, asks only for missing values, and checks the result.
