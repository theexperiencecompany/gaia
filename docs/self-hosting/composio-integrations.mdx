About 30 built-in integrations, including Gmail, Google Calendar, GitHub, Slack and Notion, connect through [Composio](https://composio.dev). On a self-hosted instance you can also add any of the 1,600+ other apps in Composio's catalog. Your users then connect them from the integrations page like any built-in one.

Each app needs an **auth config**: Composio's record of how users sign in to it. Your instance needs a Composio project of its own, and GAIA creates the auth configs in it for you.

## 1. Create a Composio project and save its key

1. Sign up at [app.composio.dev](https://app.composio.dev) and create a project.
2. Copy the project's API key from the Composio dashboard.
3. Sign in as the instance admin, open **Settings → Integrations setup** and paste the key under **Composio key**. The Composio row in **Settings → Providers & Tools** links to this page too.

<Tip>
  You can paste the key during first-run setup too: on the **Connect your accounts** step, in the **Tool keys** box.
</Tip>

## 2. Set up the built-in integrations

If your Composio project already has auth configs, GAIA fills in a match for each integration. Check each one and click **Save** at the bottom of the page. You can also paste an auth config id (it starts with `ac_`) by hand.

An integration with nothing filled in shows **Set up automatically**:

1. Click **Set up automatically**. The Composio catalog opens on that app.
2. Fill in any fields it asks for (see the table in the next section). Most apps ask for nothing.
3. Click **Set up**. GAIA creates the auth config in your Composio project.

You don't need to set a callback URL in Composio. GAIA sends users back to `{HOST}/api/v1/oauth/composio/callback` on its own.

<Note>
  **Google apps (Gmail, Calendar, Drive, Docs, Sheets, Tasks, Meet).** Composio's own Google sign-in is fine for trying things out. To show your own app name on Google's consent screen, create an OAuth client in the [Google Cloud console](https://console.cloud.google.com/apis/credentials), then create the auth config with your own credentials in the Composio dashboard and pick it here. Use the redirect URI that Composio shows in the auth config form. Enable each Google API you use (Gmail API, Google Calendar API, and so on) in the same Google Cloud project.
</Note>

## 3. Add any other app from the catalog

Click **Browse Composio catalog** in **Settings → Integrations setup**. The button works once your Composio key is saved. As the instance admin, you also see it on the integrations page, in the **Add any app to this instance** banner.

1. Search for the app, or filter by category.
2. Pick it. The catalog says how its users will sign in:

   | The catalog says | What you do |
   | --- | --- |
   | Users sign in through Composio's own app. Nothing to fill in. | Click **Enable** |
   | Each user enters their own credentials when they connect. | Click **Enable**. Each user pastes their key on Composio's connect page when they connect |
   | Composio has no shared app for this app. | Create an OAuth app with that provider, paste its details, then click **Enable** |
   | This app needs no sign-in, which GAIA can't connect yet. | Nothing: it can't be enabled yet |

   <Frame caption="Attio picked from the catalog: its users sign in through Composio, so there is nothing to fill in">
     <img src="/images/self-hosting/composio-catalog-detail.webp" width="560" alt="Composio catalog searched for Attio, with Attio marked Available and its detail pane: 105 tools in crm, a description, the note Users sign in through Composio's own app. Nothing to fill in, a note that catalog apps have no triggers, and an Enable button" />
   </Frame>

3. Click **Enable**.

The app shows up on everyone's integrations page right away, with no restart. Users click **Connect** like for any built-in integration, and GAIA can then use every tool the app has in chat and in workflows.

Apps added from the catalog differ from built-in ones:

| | Built-in integration | Added from the catalog |
| --- | --- | --- |
| Triggers (start a workflow from the app's events) | Yes | No. Workflows can still use its tools |
| How GAIA learns the tools | Hand-written instructions and custom tools | Each tool's own description |
| Approvals | For actions marked as needing one | GAIA asks before any action that looks destructive, because nobody has reviewed the tools by hand |

**Apps that need no sign-in** are listed as **No sign-in** and can't be enabled yet. Composio runs these without a connected account, and GAIA's integrations always connect one. An example is Hacker News.

To remove an app you added, open it in the catalog and click **Remove**. Its auth config and your users' connections stay in your Composio project, so you can delete them there.

## Setting auth configs from the environment

If you manage configuration in files instead, set `COMPOSIO_KEY` and map built-in integration ids to auth config ids in `COMPOSIO_AUTH_CONFIG_OVERRIDES`:

```bash
COMPOSIO_KEY=your-composio-api-key
COMPOSIO_AUTH_CONFIG_OVERRIDES={"gmail": "ac_...", "googlecalendar": "ac_...", "github": "ac_..."}
```

An id saved in **Settings → Integrations setup** takes priority over the environment. The instance refuses to start if this variable names an integration that doesn't use Composio, or gives an empty id. Apps added from the catalog are configured in the app only.

## Troubleshooting

| Message | Cause | Fix |
| --- | --- | --- |
| "Composio rejected the saved API key" | The key is wrong or was revoked | Copy a fresh key from the Composio dashboard |
| "needs ... to create its auth config" | Composio has no shared sign-in app for this app | Fill in the listed fields from an OAuth app you create with the provider |
| "Composio refused to create an auth config" | Composio's reason is in the message, usually a wrong client id or secret | Check the OAuth app's details and try again |
| An app still shows "Not set up on this instance" | It has no auth config yet | Click **Set up automatically** next to it in **Settings → Integrations setup** |

To connect MCP servers, including ones on your own network, see [MCP servers on a self-hosted instance](/self-hosting/mcp-servers).
