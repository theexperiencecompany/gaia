This page walks you from an empty Linux server to a GAIA that you and other people use every day. Every screenshot comes from a real install on a fresh virtual machine.

You need a server (or your own computer) with 8 GB of RAM and an API key from one AI provider, such as OpenAI. Nothing else.

## Install and start GAIA

<Steps>
  <Step title="Install the GAIA CLI">
    Open a terminal on the server and run:

    ```bash
    curl -fsSL https://heygaia.io/install.sh | sh
    ```

    The installer sets up Node.js if the server has none, then installs the `gaia` command. If it says `gaia` is not on your PATH yet, open a new terminal or run the line it prints.

    <Frame caption="The installer on a fresh Linux server">
      <img src="/images/self-hosting/terminal-install.webp" width="579" alt="Terminal output of the GAIA install script: it detects Linux, installs Node.js through nvm, installs the GAIA CLI and lists the gaia up, gaia status and gaia --help commands" />
    </Frame>
  </Step>

  <Step title="Run gaia up">
    ```bash
    gaia up
    ```

    This installs Docker if it is missing, downloads GAIA and starts it. When it finishes, it prints the address to open. You can paste your AI key in the browser afterwards.

    <Frame caption="gaia up finishes with the addresses to open GAIA at and the link to finish setup in the browser">
      <img src="/images/self-hosting/terminal-gaia-up.webp" width="635" alt="Terminal output of gaia up: every setup step checked, then a GAIA is ready box listing the localhost and local-network addresses, the API address, the browser setup link, and a note that code execution stays off until an E2B key is saved or gaia up reruns with --code-sandbox" />
    </Frame>

    To change how it starts, add flags. Most people need none.

    | Flag | What it does | Default |
    | ---- | ------------ | ------- |
    | `--yes` | Installs git and Docker without asking when they are missing (apt-based Linux). Nothing else in `gaia up` asks a question | Asks before installing |
    | `--llm-provider <provider>` | Saves an AI provider once GAIA is up, so you can skip that step in the browser: `openai`, `openrouter`, `gemini`, `ollama` or `custom` | None |
    | `--llm-key <key>` | The provider's API key. Required for `openai`, `openrouter`, `gemini` and `custom`. Not used with `ollama` | None |
    | `--llm-base-url <url>` | The provider's address. Required for `custom`. Optional for `ollama` | `http://host.docker.internal:11434` for `ollama` |
    | `--llm-model <model>` | The model to use. Required for `custom`. Optional for `ollama` | None |
    | `--web-port <port>` | The port GAIA is served on | 3000 |
    | `--domain <domain>` | Serves GAIA at `https://<domain>` with an automatic certificate. Uses ports 80 and 443 | Off |
    | `-b, --build` | Builds the images from this checkout instead of downloading them | Downloads them |
    | `--code-sandbox` | Turns on the local code sandbox. It is kept on later starts and updates | Off |
    | `--no-code-sandbox` | Turns the local code sandbox off again | Not applicable |
    | `--no-start` | Sets everything up but does not start GAIA. Can't be combined with the `--llm-` flags, which save the provider into the running GAIA | Starts GAIA |
    | `--force-dev-tree` | Lets the command run in a developer checkout that is not your recorded install | Off |

    For example, to start GAIA with an AI provider already saved:

    ```bash
    # OpenAI (or openrouter, gemini): just the key
    gaia up --llm-provider openai --llm-key sk-...

    # A local Ollama: no key
    gaia up --llm-provider ollama --llm-model qwen3

    # Any OpenAI-compatible gateway: key, address and model
    gaia up --llm-provider custom --llm-key sk-... --llm-base-url https://gateway.example.com/v1 --llm-model some-model
    ```

    The provider is saved the same way the browser setup saves it, so it shows as saved in **Settings → Providers & Tools** and you can change it there. If GAIA doesn't answer in time, `gaia up` stops and says the provider wasn't saved. Once `gaia status` shows GAIA healthy, run the same `gaia up` command again. The code sandbox is explained in [Run code](#run-code-optional) below.
  </Step>

  <Step title="Open the printed address">
    Open the setup address in a browser on any device that can reach the server. On your home or office network that is the `192.168.x.x` address. On the server itself, `http://localhost:3000` works too.

    For a public domain with HTTPS, start GAIA with `gaia up --domain gaia.example.com` instead. See [HTTPS on your own domain](/self-hosting/docker-setup#https-on-your-own-domain).
  </Step>
</Steps>

## Finish setup in the browser

<Steps>
  <Step title="Create the admin account">
    The first account you create is the admin of this GAIA. Pick a name, your email and a password of at least 8 characters.

    <Frame caption="The first account becomes the admin">
      <img src="/images/self-hosting/setup-admin-account.webp" width="560" alt="Setup step titled Create your admin account, with the name Ada Lovelace, the email ada@example.com and a hidden password filled in, above a Create account button" />
    </Frame>
  </Step>

  <Step title="Connect an AI provider">
    GAIA needs one AI provider to think with. If you passed `--llm-provider` to `gaia up`, it is already connected and you can press **Continue**. Otherwise, pick one:

    | Tab | What you do |
    | --- | --- |
    | **Hosted key** | Paste an OpenRouter key, or click **More providers** for OpenAI, Google Gemini or a custom OpenAI-compatible server. Then click **Test & Save** |
    | **Local Ollama · free** | Use an Ollama running on your machine. No key needed |
    | **Skip for now** | Set it up later. GAIA can't chat until you do |

    GAIA tests the key and saves it only if the provider answers.

    <Frame caption="OpenAI connected with a pasted key">
      <img src="/images/self-hosting/setup-ai-provider.webp" width="560" alt="Setup step titled Choose an AI provider, showing OpenAI is connected and saved on this instance, with Change provider, Back, Continue and Skip for now" />
    </Frame>
  </Step>

  <Step title="Add the optional extras, or skip them">
    The next two screens are optional. You do not need anything on them. Paste a key if you have one, or press **Continue**:

    - **Web search** works for free with DuckDuckGo. Pick Tavily, Exa, Brave Search or your own SearXNG for better results.
    - **Connect your accounts** lists apps you can connect, and **Tool keys** such as Composio and E2B.

    The last screen, **You're all set**, shows what is configured. Click **Start chatting**.

    Web search, reading web pages and file storage already work without a key. See [what works out of the box](/self-hosting/overview#what-works-out-of-the-box).

    You can add a key at any time in **Settings → Providers & Tools**. Each feature shows **Working** or **Off** there, and which provider it is using.

    <Frame caption="An optional step: better web search with a Tavily, Exa or Brave key">
      <img src="/images/self-hosting/setup-web-search.webp" width="560" alt="Setup step titled Web search, using DuckDuckGo for free with no key, a Provider picker set to Tavily with an API key field and a Save button, and Back, Continue and Skip for now" />
    </Frame>
  </Step>

  <Step title="Land on the home screen">
    Setup is done. A banner at the top of the home screen lists the optional features that are still off. Click **Show** to see them, **Set up** to add one, or the cross to hide one you don't want.

    <Frame caption="The setup banner, opened with Show">
      <img src="/images/self-hosting/home-setup-banner.webp" width="560" alt="Setup banner reading 3 setup steps left, opened to list Email, Integrations and Weather, each with a Set up button and a dismiss cross" />
    </Frame>
  </Step>
</Steps>

### The setup banner and First steps

Two checklists help you get started. They track different things:

| | Setup banner | First steps |
| --- | --- | --- |
| Who sees it | Only the admin | Every member, each with their own list |
| What it tracks | The instance: the AI provider and admin account, then every optional feature that is still off, such as email, integrations or weather | You: say hi to GAIA, connect an integration, link a messaging app and create a workflow |
| Where it shows | At the top of the home screen | A panel in the bottom-right corner (not on phones), and a card on the dashboard |
| When it goes away | When nothing is left to set up. You can hide one item, or the whole banner | When you have done every step. You can collapse the panel until then |

The setup banner is about the server, so members never see it. First steps is about each person, so a new member starts with their own.

### Run code (optional)

GAIA can write and run code for you, but only if you turn on a code sandbox. You have two choices:

- **E2B** (recommended): save an [E2B](https://e2b.dev) key in **Settings → Providers & Tools**. Code runs on E2B's servers, not yours.
- **Local sandbox**: start GAIA with `gaia up --code-sandbox`. Code runs in containers on your own server.

<Warning>
  The local sandbox gives GAIA's API and worker access to your server's Docker. That is the same as root access to the server. Only turn it on for a server you trust everyone on, and never on a shared machine. Turn it off with `gaia up --no-code-sandbox`. See [Local coding sandbox](/self-hosting/docker-setup#local-coding-sandbox).
</Warning>

## Change settings later

### Providers & Tools

Open **Settings → Providers & Tools** to add, change or remove AI providers, and to add web search or a code sandbox. Changes apply right away, with no restart.

<Frame caption="Settings → Providers & Tools">
  <img src="/images/self-hosting/settings-providers-tools.webp" width="560" alt="Providers and Tools settings: AI models marked Working and using OpenAI, with the provider picker, the stored key, the model and Remove, Test and Test and Save buttons; Web search marked Working and using DuckDuckGo, with a provider picker set to Tavily and a Save button" />

### Connect apps like Gmail and Calendar

Apps such as Gmail, Google Calendar and Notion connect through your own Composio project. Paste your Composio key in **Settings → Integrations setup**. If your Composio project already has auth configs, GAIA fills in a match for each integration for you to check and save. Any integration left empty has a **Set up automatically** button that creates one. Follow [Connect integrations](/self-hosting/composio-integrations) for the full steps.

## Invite other people

<Steps>
  <Step title="Create an invite link">
    Open **Settings → Members** and press **Create link**. Copy the link and send it to the person you want to invite. Each link works for one person and expires after 7 days. You can only copy it right after you create it.

    Everyone gets their own private chats, tasks and connected apps. They share your AI provider keys, and only you can change them.

    <Frame caption="Settings → Members, with a new invite link">

## Keep GAIA up to date

```bash
gaia update
```

This moves GAIA to the release your CLI ships and keeps your chats, accounts and settings. To get a newer GAIA, update the CLI first by running the install command again, then run `gaia update`.

Back up your data now and then:

```bash
gaia backup                  # saves your data to ./backups/
gaia restore --from backups  # restores the latest backup
```

See [Backups](/self-hosting/docker-setup#backups) for what is included and how to store backups somewhere safe.
