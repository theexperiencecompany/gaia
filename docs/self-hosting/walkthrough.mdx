Go from an empty server to a GAIA your team uses, in about ten minutes.

You need a server or computer with 8 GB of RAM, and an API key from one AI provider such as OpenAI.

## Install and start GAIA

<Steps>
  <Step title="Install the GAIA CLI">
    Open a terminal on the server and run:

    ```bash
    curl -fsSL https://heygaia.io/install.sh | sh
    ```

    If it says `gaia` is not found, open a new terminal.

    <Frame caption="The installer on a fresh Linux server: it installs Node.js and the GAIA CLI, then offers to set GAIA up">
      <img src="/images/self-hosting/terminal-install.webp" width="640" alt="Terminal output of the GAIA installer: the GAIA logo, Node.js and the GAIA CLI installed with their timings, then a spinner on Installing Docker with its sub-steps listed" />
    </Frame>

    <Frame caption="Setup downloads Docker, then GAIA, with live progress and timings">
      <img src="/images/self-hosting/terminal-install-download.webp" width="640" alt="Terminal output of the installer mid-download: Docker packages at 38 of 110 MB with elapsed time" />
    </Frame>
  </Step>

  <Step title="Run gaia up">
    ```bash
    gaia up
    ```

    It installs Docker if needed, downloads GAIA and starts it. When it finishes, it prints the address to open.

    <Frame caption="When setup finishes, GAIA prints the address to open and the command shortcuts">
      <img src="/images/self-hosting/terminal-gaia-up.webp" width="635" alt="Terminal output at the end of setup: Node.js, the GAIA CLI, Docker, and GAIA each checked with timings, then a GAIA is running box with the setup link to create your admin account, the localhost address, and the gaia status, stop, doctor and --help shortcuts" />
    </Frame>

    Want your AI provider saved at the same time? Add it here and skip that step in the browser:

    ```bash
    gaia up --llm-provider openai --llm-key sk-...
    ```

    <Accordion title="More options (domain, port, Ollama, other providers)">
      | Flag | What it does |
      | --- | --- |
      | `--domain <domain>` | Serves GAIA at `https://<domain>` with an automatic certificate. Uses ports 80 and 443 |
      | `--web-port <port>` | Changes the port. Default 3000 |
      | `--llm-provider <name>` | `openai`, `openrouter`, `gemini`, `ollama` or `custom` |
      | `--llm-key <key>` | The provider's key. Not used with `ollama` |
      | `--llm-base-url <url>` | The provider's address. Needed for `custom` |
      | `--llm-model <model>` | The model. Needed for `custom` |
      | `--code-sandbox` | Turns on the local code sandbox. See [Run code](#run-code-optional) |

      ```bash
      # A local Ollama: no key
      gaia up --llm-provider ollama --llm-model qwen3

      # Any OpenAI-compatible gateway
      gaia up --llm-provider custom --llm-key sk-... --llm-base-url https://gateway.example.com/v1 --llm-model some-model
      ```

      The provider is saved like the browser setup saves it, so you can change it later in **Settings → Providers & Tools**. If GAIA is slow to start, `gaia up` says the provider wasn't saved. Run the same command again once `gaia status` shows GAIA healthy. Every flag is in the [CLI reference](/self-hosting/cli-reference#gaia-up).
    </Accordion>
  </Step>

  <Step title="Open the printed address">
    On the server, `http://localhost:3000` works. From another device on your network, use the `192.168.x.x` address.
  </Step>
</Steps>

## Finish setup in the browser

<Steps>
  <Step title="Create the admin account">
    The first account is the admin. Use a password of at least 8 characters.

    <Frame caption="The first account becomes the admin">
      <img src="/images/self-hosting/setup-admin-account.webp" width="560" alt="Setup step titled Create your admin account, with the name Ada Lovelace, the email ada@example.com and a hidden password filled in, above a Create account button" />
    </Frame>
  </Step>

  <Step title="Connect an AI provider">
    GAIA needs one AI provider. If you passed `--llm-provider`, press **Continue**. Otherwise pick one:

    | Tab | What you do |
    | --- | --- |
    | **Hosted key** | Paste an OpenRouter key, or click **More providers** for OpenAI, Google Gemini or a custom OpenAI-compatible server. Then click **Test & Save** |
    | **Local Ollama · free** | Use an Ollama running on your machine. No key needed |
    | **Skip for now** | Set it up later. GAIA can't chat until you do |

    <Frame caption="OpenAI connected with a pasted key">
      <img src="/images/self-hosting/setup-ai-provider.webp" width="560" alt="Setup step titled Choose an AI provider, showing OpenAI is connected and saved on this instance, with Change provider, Back, Continue and Skip for now" />
    </Frame>
  </Step>

  <Step title="Add the optional extras, or skip them">
    The next screens are optional. Paste a key if you have one, or press **Continue**:

    - **Web search** works for free with DuckDuckGo. Tavily, Exa, Brave Search or your own SearXNG give better results.
    - **Tool keys** such as Composio and E2B, and apps you can connect.

    Then click **Start chatting**. Add keys any time in **Settings → Providers & Tools**; see [AI models and tools](/self-hosting/ai-models-and-tools#tools).

    <Frame caption="An optional step: better web search with a Tavily, Exa or Brave key">
      <img src="/images/self-hosting/setup-web-search.webp" width="560" alt="Setup step titled Web search, using DuckDuckGo for free with no key, a Provider picker set to Tavily with an API key field and a Save button, and Back, Continue and Skip for now" />
    </Frame>
  </Step>

  <Step title="Land on the home screen">
    A banner lists optional features that are still off. Click **Show** to see them, or **Set up** to add one.

    <Frame caption="The setup banner, opened with Show">
      <img src="/images/self-hosting/home-setup-banner.webp" width="560" alt="Setup banner reading 3 setup steps left, opened to list Email, Integrations and Weather, each with a Set up button and a dismiss cross" />
    </Frame>
  </Step>
</Steps>

<Accordion title="Setup banner vs First steps">
  | | Setup banner | First steps |
  | --- | --- | --- |
  | Who sees it | Only the admin | Every member, each their own |
  | What it tracks | The server: AI provider, then optional features still off | You: say hi, connect an app, link a messaging app, create a workflow |
  | Where | Top of the home screen | Bottom-right panel (not on phones) and a dashboard card |
  | Goes away | When nothing is left, or when you hide it | When every step is done, or when you collapse it |
</Accordion>

### Run code (optional)

GAIA can run code only if you turn on a sandbox:

- **E2B** (recommended): save an [E2B](https://e2b.dev) key in **Settings → Providers & Tools**. Code runs on E2B's servers.
- **Local sandbox**: run `gaia up --code-sandbox`. Code runs on your own server.

<Warning>
  The local sandbox gives GAIA root-level access to your server. Use it only where you trust everyone. Turn it off with `gaia up --no-code-sandbox`. See [Running code](/self-hosting/ai-models-and-tools#running-code).
</Warning>

## Change settings later

### Providers & Tools

Open **Settings → Providers & Tools** to change AI providers, web search or the code sandbox. Changes apply right away.

<Frame caption="Settings → Providers & Tools">
  <img src="/images/self-hosting/settings-providers-tools.webp" width="560" alt="Providers and Tools settings: AI models marked Working and using OpenAI, with the provider picker, the stored key, the model and Remove, Test and Test and Save buttons; Web search marked Working and using DuckDuckGo, with a provider picker set to Tavily and a Save button" />

### Connect apps like Gmail and Calendar

Apps connect through your own Composio project. Paste its key in **Settings → Integrations setup**. Full steps: [Connect integrations](/self-hosting/composio-integrations).

## Invite other people

<Steps>
  <Step title="Create an invite link">
    Open **Settings → Members** and press **Create link**. Copy it right away and send it. Each link works once and expires after 7 days.

    Everyone gets private chats, tasks and apps. They share your AI keys, which only you can change.

    <Frame caption="Settings → Members, with a new invite link">
      <img src="/images/self-hosting/settings-members-invite.webp" width="560" alt="Members settings with the Open sign-up switch off, a freshly created invite link with a copy button, the unused invite with a Revoke button, and Ada Lovelace listed as Admin" />
    </Frame>

    Or turn on **Open sign-up** to let anyone who can reach your GAIA join.
  </Step>

  <Step title="Your teammate signs up">
    They open the link and create an account.

    <Frame caption="Signing up from an invite link">
      <img src="/images/self-hosting/member-signup.webp" width="384" alt="Create your account page reading Join this GAIA instance, filled in with the name Grace Hopper and the email grace@example.com" />
    </Frame>

    They land on their own home screen.

    <Frame caption="The new member's own GAIA">
      <img src="/images/self-hosting/member-home.webp" width="560" alt="GAIA home screen greeting Grace by name, with the message box and suggested prompts" />
    </Frame>

    If a link was used or expired, create a new one.
  </Step>

  <Step title="Sign in next time">
    Everyone signs in with email and password at the same address.

## Check on it

Run `gaia status` to see if each part is running. If something seems wrong, run `gaia doctor`. It prints a fix for each problem.

## Update and back up

```bash
gaia update
```

Your chats, accounts and settings stay. For a newer GAIA, run the install command again first.

```bash
gaia backup
```

Backups go to `./backups/`. See [Backups](/self-hosting/maintenance#backups) to restore and store them safely.
