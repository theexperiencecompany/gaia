This guide is for people who want to run GAIA with plain `docker compose` and not install the `gaia` CLI. You get the same stack `gaia up` starts, and you do by hand the few things it does for you: download the setup files, write two settings files and start the containers.

<Note>
  Happy to use the CLI? The [self-hosting walkthrough](/self-hosting/walkthrough) does all of this with one command, and `gaia doctor`, `gaia update` and `gaia backup` only work on top of it.
</Note>

## Prerequisites

- **Docker** with Compose v2: Docker Desktop on macOS or Windows, Docker Engine 20.10+ on Linux, or OrbStack.
- **8 GB of RAM**, 2+ CPU cores and 10 GB of free disk. See [Memory sizing](/self-hosting/maintenance#memory-sizing) for why.
- **Port 3000** free on the machine, or ports 80 and 443 to serve a domain over HTTPS.
- `curl` and `openssl`. Git is not needed.

<Accordion icon="docker" title="Installing Docker Engine on Ubuntu or Debian">
  ```bash
  sudo apt-get update
  sudo apt-get install -y docker.io docker-compose-plugin
  sudo systemctl enable --now docker
  sudo usermod -aG docker $USER
  newgrp docker
  ```

  On macOS or Windows, install [Docker Desktop](https://docs.docker.com/desktop/) instead.
</Accordion>

## Install

<Steps>
  <Step title="Check Docker">
    ```bash
    docker compose version
    ```

    **You should see** `Docker Compose version v2.` followed by a version number. An error means Docker or its Compose plugin is missing.
  </Step>

  <Step title="Download the setup files">
    Each GAIA release publishes its setup files as `gaia-selfhost-<version>.tar.gz` on its [GitHub Release](https://github.com/theexperiencecompany/gaia/releases), with a checksum next to it. Set `V` to the version you want, then download, check and unpack it into `~/gaia`:

    ```bash
    V=0.7.0
    BASE=https://github.com/theexperiencecompany/gaia/releases/download/cli-v$V
    mkdir -p ~/gaia && cd ~/gaia
    curl -fsSLO "$BASE/gaia-selfhost-$V.tar.gz"
    curl -fsSLO "$BASE/gaia-selfhost-$V.tar.gz.sha256"
    sha256sum -c "gaia-selfhost-$V.tar.gz.sha256"
    tar -xzf "gaia-selfhost-$V.tar.gz" && rm -f "gaia-selfhost-$V.tar.gz"*
    ```

    On macOS, use `shasum -a 256 -c` instead of `sha256sum -c`.

    **You should see** `gaia-selfhost-0.7.0.tar.gz: OK`. Afterwards `ls` shows `gaia-selfhost.json` (the list of setup files) and `infra/`, which holds the Compose files and the proxy's `Caddyfile`.
  </Step>

  <Step title="Write the API settings">
    From `~/gaia`, write `apps/api/.env`. The `openssl` lines fill in random secrets as the file is written:

    ```bash
    mkdir -p apps/api
    cat > apps/api/.env <<EOF
    ENV=selfhost
    AUTH_MODE=local
    HOST=http://localhost:3000
    FRONTEND_URL=http://localhost:3000
    MONGO_DB=mongodb://mongo:27017/gaia
    REDIS_URL=redis://redis:6379
    POSTGRES_URL=postgresql://postgres:postgres@postgres:5432/langgraph
    CHROMADB_HOST=chromadb
    CHROMADB_PORT=8000
    RABBITMQ_URL=amqp://guest:guest@rabbitmq:5672/
    AGENT_SECRET=$(openssl rand -hex 32)
    BOT_SESSION_TOKEN_SECRET=$(openssl rand -hex 32)
    EMAIL_UNSUBSCRIBE_SECRET=$(openssl rand -hex 32)
    SHARE_GRANT_SECRET=$(openssl rand -hex 32)
    INSTANCE_SECRET=$(openssl rand -hex 32)
    EOF
    chmod 600 apps/api/.env
    ```

    **You should see** no output. `cat apps/api/.env` shows each secret as a long random string, not as `$(openssl rand -hex 32)`.

    Write this file once and keep it. `INSTANCE_SECRET` encrypts the provider keys you save later, so changing it or the other secrets once GAIA has data signs everyone out and makes saved keys unreadable. See [The instance secret](/self-hosting/maintenance#the-instance-secret). Serving GAIA on a domain? Change `HOST` and `FRONTEND_URL` to that address; see [Your own domain with HTTPS](#your-own-domain-with-https).
  </Step>

  <Step title="Write the Compose settings">
    ```bash
    cat > infra/docker/.env <<EOF
    COMPOSE_PROFILES=proxy
    GAIA_VERSION=v$V
    EOF
    ```

    `COMPOSE_PROFILES=proxy` starts the proxy, the only container that opens a port. Without it nothing can reach GAIA. `GAIA_VERSION` pins the images to the release whose setup files you downloaded.

    **You should see** no output. `cat infra/docker/.env` shows both lines, with your version, for example `GAIA_VERSION=v0.7.0`.
  </Step>

  <Step title="Start GAIA">
    ```bash
    cd ~/gaia/infra/docker
    docker compose -f docker-compose.selfhost.yml up -d
    ```

    Always pass `-f docker-compose.selfhost.yml`: Compose doesn't find this file on its own.

    **You should see** the images download, then each container listed as `Started` or `Healthy`. The first start can take several minutes while the API sets up its databases.
  </Step>

  <Step title="Check that it's healthy">
    ```bash
    docker compose -f docker-compose.selfhost.yml ps
    curl http://localhost:3000/health/ready
    ```

    **You should see** every service `Up` and `(healthy)` in the first command, and a JSON report from the second where every dependency is healthy. If `gaia-backend` still says `(health: starting)`, wait a minute and run it again.
  </Step>

  <Step title="Finish setup in the browser">
    Open `http://localhost:3000` (or your server's address in place of `localhost`).

    **You should see** the setup page. Create the admin account, then pick an AI provider. See [AI models and tools](/self-hosting/ai-models-and-tools) for the choices.
  </Step>
</Steps>

## Options

Set these in `infra/docker/.env`, then run `docker compose -f docker-compose.selfhost.yml up -d` again to apply them.

| Variable | What it does | Default |
| --- | --- | --- |
| `GAIA_VERSION` | The image tag for the API, worker and web app | `latest` |
| `WEB_HOST_PORT` | The port GAIA is served on | `3000` |
| `HTTPS_HOST_PORT` | The HTTPS port | `3443` |
| `GAIA_DOMAIN` | A domain to serve over HTTPS with an automatic certificate | Unset: plain HTTP |
| `COMPOSE_PROFILES` | `proxy` starts the bundled proxy. Leave it out when you bring your own | Unset: no proxy |
| `GAIA_API_IMAGE`, `GAIA_WEB_IMAGE` | Use other images, such as your own builds | `ghcr.io/theexperiencecompany/gaia`, `ghcr.io/theexperiencecompany/gaia-web` |

For the local coding sandbox, add a second Compose file: `docker compose -f docker-compose.selfhost.yml -f docker-compose.sandbox.yml up -d`. Read [Running code](/self-hosting/ai-models-and-tools#running-code) first: it gives the containers root access to your server. Chat bots need the CLI (`gaia bots add`); see [Chat bots](/self-hosting/bots).

API settings such as provider keys and `BLOB_STORE` go in `apps/api/.env`; see [AI models and tools](/self-hosting/ai-models-and-tools) and [Environment variables](/configuration/environment-variables).

### Your own domain with HTTPS

Point the domain's DNS at your server, and make sure ports 80 and 443 are open to the internet. Then set `HOST` and `FRONTEND_URL` in `apps/api/.env` to `https://gaia.example.com`, add these to `infra/docker/.env`, and start again:

```bash
GAIA_DOMAIN=gaia.example.com
WEB_HOST_PORT=80
HTTPS_HOST_PORT=443
```

The proxy gets and renews a Let's Encrypt certificate and sends plain HTTP visitors to HTTPS. For a name no public authority can certify (`gaia.test`, `*.internal`, `*.home.arpa`), see [A local domain with HTTPS](/self-hosting/cli-reference#a-local-domain-with-https).

### Your own reverse proxy

Platforms with their own proxy (Coolify, Traefik and others) don't need the bundled one. Leave `COMPOSE_PROFILES` unset and route on the Compose network:

| Path | Send to |
| --- | --- |
| `/api/v1/*` and `/health/ready` | `gaia-backend:8000` |
| Everything else | `gaia-web:3000` |

Don't buffer streamed responses, allow WebSocket upgrades on `/api/v1`, and make your proxy replace, not append to, any `X-Forwarded-For` header a client sends: the API trusts it for rate limits. If you put another proxy in front of the bundled one instead (Cloudflare Tunnel, a load balancer), add its address to [`trusted_proxies`](https://caddyserver.com/docs/caddyfile/options#trusted-proxies) in `infra/docker/selfhost/Caddyfile`, or every visitor shares one rate limit.

## Day-to-day commands

Run these from `~/gaia/infra/docker`.

| To | Run |
| --- | --- |
| See container status | `docker compose -f docker-compose.selfhost.yml ps` |
| Follow the logs | `docker compose -f docker-compose.selfhost.yml logs -f gaia-backend` |
| Restart a service | `docker compose -f docker-compose.selfhost.yml restart gaia-backend` |
| Stop GAIA | `docker compose -f docker-compose.selfhost.yml down` |
| Open a database shell | `docker compose -f docker-compose.selfhost.yml exec mongo mongosh gaia` |

Containers have no fixed names, so always go through `docker compose` with the service name, not `docker logs`.

<Warning>
  Never run `down -v` or `docker system prune --volumes`: they delete every volume, which is all of GAIA's data. See [Data persistence](/self-hosting/maintenance#data-persistence).
</Warning>

Updates, backups and restores have manual steps too: see [Upgrades](/self-hosting/maintenance#upgrades) and [Backups](/self-hosting/maintenance#backups).

## What's running

| Service | What it does |
| --- | --- |
| `proxy` | Caddy, the only service with a host port. Sends `/api/v1/*` and `/health/ready` to the API and everything else to the web app |
| `gaia-web` | The Next.js web app |
| `gaia-backend` | The FastAPI API |
| `arq_worker` | Background jobs: reminders, workflows, email. Same image as the API |
| `mongo` | Accounts, chats, settings and saved provider keys |
| `postgres` | Agent state |
| `redis` | Cache, sessions and the job queue |
| `chromadb` | Vectors for memory and search |
| `rabbitmq` | Message broker |

The databases run without passwords (RabbitMQ uses the well-known `guest`/`guest`) and are reachable only on the internal Compose network.

<Warning>
  Don't add `ports:` for the databases to the Compose file. Between them they hold every account, session, saved key and the instance secret, so an open port means anyone can take all of it.
</Warning>

## Troubleshooting

<AccordionGroup>
  <Accordion icon="plug" title="http://localhost:3000 doesn't load">
    Check that `infra/docker/.env` has `COMPOSE_PROFILES=proxy` and that `docker compose -f docker-compose.selfhost.yml ps` lists `proxy`. Without the profile no port is opened. If something else uses port 3000, set `WEB_HOST_PORT` to another port.
  </Accordion>
  <Accordion icon="hourglass" title="gaia-backend stays unhealthy">
    The first start sets up the databases and can take up to 10 minutes on a small machine. Watch it with `docker compose -f docker-compose.selfhost.yml logs -f gaia-backend`. An error that names a missing setting means a line is missing from `apps/api/.env`: compare it with [step 3](#install).
  </Accordion>
  <Accordion icon="memory" title="Containers restart once memory is in use">
    The machine is out of memory. GAIA needs 8 GB; see [Memory sizing](/self-hosting/maintenance#memory-sizing).
  </Accordion>
  <Accordion icon="file" title="docker compose says no configuration file was found">
    You left out `-f docker-compose.selfhost.yml`. Compose only finds `docker-compose.yml` on its own, and the setup files don't include one. Add `-f docker-compose.selfhost.yml` to every command.
  </Accordion>
  <Accordion icon="stethoscope" title="Something else">
    See [Troubleshooting](/self-hosting/maintenance#troubleshooting), including Ollama connection problems.
  </Accordion>
</AccordionGroup>

## Building from source

To run your own changes, build the images from a source checkout instead of pulling them. From `infra/docker/` in the checkout:

```bash
docker compose -f docker-compose.selfhost.yml -f docker-compose.build.yml up -d --build
```

The build keeps the same image tags, so a later plain `up` uses your build until the next pull. For hot reload and the full developer setup, see [Development setup](/developers/development-setup).
