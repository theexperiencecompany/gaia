Install the `gaia` CLI, run `gaia up`, and finish setup in your browser.

## Install and start

<Steps>
  <Step title="Install the CLI">
    ```bash
    curl -fsSL https://heygaia.io/install.sh | sh
    ```

    <Accordion title="Other ways to install">
      <Snippet file="cli-install.mdx" />
    </Accordion>

    <Frame caption="The installer on a fresh Linux server">
      <img src="/images/self-hosting/terminal-install.webp" width="579" alt="Terminal output of the GAIA install script: it detects Linux, installs Node.js through nvm, installs the GAIA CLI and lists the gaia up, gaia status and gaia --help commands" />
    </Frame>
  </Step>

  <Step title="Start GAIA">
    ```bash
    gaia up
    ```

    It checks Docker (and offers to install it), downloads GAIA into `~/gaia`, writes the settings and starts everything. Git is not needed.
  </Step>

  <Step title="Finish in the browser">
    Open http://localhost:3000/setup, create the admin account and pick an AI provider.
  </Step>
</Steps>

New to this? The [walkthrough](/self-hosting/walkthrough) shows every step with screenshots.

## Everyday commands

| Command | What it does |
| --- | --- |
| `gaia status` | Shows each service and whether it is healthy |
| `gaia doctor` | Finds what is broken and tells you how to fix it |
| `gaia logs` | Streams logs |
| `gaia stop` / `gaia start` | Stops and starts GAIA |
| `gaia update` | Moves to the GAIA release your CLI ships. Your data stays |
| `gaia backup` / `gaia restore` | Saves and restores your data |

Every flag and command is in the [CLI reference](/self-hosting/cli-reference).

## Update

```bash
gaia update
```

Each CLI version ships one tested GAIA release. To get a newer GAIA, update the CLI first with the install command above, then run `gaia update`. If the download fails, nothing changes.

## Something broke?

```bash
gaia doctor
```

It checks Docker, containers, ports, every database, the web app, disk and memory, and prints a fix for each problem.

## Good to know

<AccordionGroup>
  <Accordion title="Port 3000 is taken">
    GAIA opens one port. If it is busy, `gaia up` shows what uses it and suggests another. The choice is saved in `infra/docker/.env` inside `~/gaia`. To change it later, edit that file, then run `gaia stop && gaia start`.

    | Variable | What it sets | Default |
    | --- | --- | --- |
    | `WEB_HOST_PORT` | The HTTP port | 3000 |
    | `HTTPS_HOST_PORT` | The HTTPS port, used with `GAIA_DOMAIN` | 3443 |
    | `GAIA_DOMAIN` | Your domain (set by `--domain`) | unset |
  </Accordion>

  <Accordion title="Try a beta">
    Betas are early versions, numbered like `0.7.0-beta.1`. Add `GAIA_CHANNEL=beta` to the install command, then run `gaia up`:

    ```bash
    curl -fsSL https://heygaia.io/install.sh | GAIA_CHANNEL=beta sh
    ```

    Expect rough edges, and run `gaia backup` first if you rely on the install.
  </Accordion>

  <Accordion title="What is in ~/gaia">
    - `infra/docker/`: the Compose files and proxy settings
    - Your files: `apps/api/.env`, `apps/bots/.env`, `infra/docker/.env` and `backups/`
    - `gaia-selfhost.json`: the list of files that came with the release

    Run the commands from inside this folder.
  </Accordion>

  <Accordion title="Installs made by an older gaia up">
    These were git checkouts. The next `gaia update` converts them: the tracked files and `.git` are removed, and your settings and backups stay. A checkout on a branch, or with local edits, is refused and pointed at `gaia update --git`.
  </Accordion>
</AccordionGroup>
