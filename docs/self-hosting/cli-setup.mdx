The GAIA CLI is the primary way to set up self-hosted GAIA. One command starts the whole stack and hands you off to the browser to finish setup — no hand-editing environment files.

<Info>
  For installation instructions, see [CLI Installation](/cli/installation). For
  the full command reference, see [CLI Commands](/cli/commands).
</Info>

## Install

<Snippet file="cli-install.mdx" />

Or with the standalone installer (no Node.js needed):

```bash
curl -fsSL https://heygaia.io/install.sh | sh
```

## Quick Start

```bash
gaia up
```

That's the whole setup. When the command finishes it prints `http://localhost:3000` — open it, create your admin account, paste an AI provider key, and start chatting. The browser-side steps are covered in [Self-hosting overview](/self-hosting/overview).

## What `gaia up` Does

<Steps>
  <Step title="Prerequisite check">
    Verifies Docker is installed and running. If Docker is missing, the CLI offers to install it for you instead of failing.
  </Step>

  <Step title="Repository setup">
    Reuses an existing GAIA checkout if you have one; otherwise clones the repository (default: `~/gaia`).
  </Step>

  <Step title="Environment configuration">
    Writes minimal `.env` files with self-host defaults: `ENV=selfhost` and `AUTH_MODE=local`. The three required machine secrets (`AGENT_SECRET`, `BOT_SESSION_TOKEN_SECRET`, `EMAIL_UNSUBSCRIBE_SECRET`) are generated automatically — you never see or type them. Port conflicts are resolved by picking free ports.
  </Step>

  <Step title="Start the stack">
    Pulls the published images (falling back to a local build if needed) and starts every service via Compose.
  </Step>

  <Step title="Hand-off">
    Prints the web URL so you can finish setup in the browser at http://localhost:3000/setup.
  </Step>
</Steps>

## Command Reference

| Command        | What it does                                                        |
| -------------- | ------------------------------------------------------------------- |
| `gaia up`      | One-command start: checks prerequisites, configures, starts         |
| `gaia doctor`  | Diagnoses a broken stack and prints a named fix per problem          |
| `gaia init`    | Full interactive wizard (clone, configure, start)                    |
| `gaia setup`   | Re-configure an existing GAIA repository                             |
| `gaia start`   | Start services (add `--pull --build` after updating)                 |
| `gaia stop`    | Stop services                                                        |
| `gaia status`  | Show which services are running                                      |
| `gaia logs`    | Stream logs                                                          |
| `gaia dev`     | Run in development mode (for contributors — see [Development setup](/developers/development-setup)) |

## Already Have the Repo?

If you've already cloned GAIA, run the management commands from inside the repository, or reconfigure it directly:

```bash
cd /path/to/gaia
gaia setup
```

This skips cloning and goes straight to environment configuration and project setup.

## Monitoring Logs

Use `gaia logs` to stream logs for currently running services.

In developer mode, `gaia dev` runs in the foreground and shows Nx TUI output in the same terminal. Keep that terminal open, and use another terminal for `gaia logs` when needed.

## Diagnosing Problems

When something isn't working, run:

```bash
gaia doctor
```

It walks the whole stack in order — Docker daemon, containers, API health endpoint, setup status (models seeded, plans seeded, provider configured, admin account created), web reachability, disk headroom — and prints what's broken with a specific fix for each problem.

## Port Conflict Handling

If required ports are already in use, the CLI detects the conflict, shows which process is using the port, and suggests an alternative port. Infrastructure URLs in your `.env` files are automatically updated to use the alternative ports.

Port overrides are saved to `infra/docker/.env` inside your GAIA repo and persist across restarts.

To change port assignments after setup, edit `infra/docker/.env` directly:

| Variable             | Service    | Default |
| -------------------- | ---------- | ------- |
| `API_HOST_PORT`      | API        | 8000    |
| `WEB_HOST_PORT`      | Web        | 3000    |
| `POSTGRES_HOST_PORT` | PostgreSQL | 5432    |
| `REDIS_HOST_PORT`    | Redis      | 6379    |
| `MONGO_HOST_PORT`    | MongoDB    | 27017   |
| `RABBITMQ_HOST_PORT` | RabbitMQ   | 5672    |
| `CHROMADB_HOST_PORT` | ChromaDB   | 8080    |

<Info>Restart services after editing: `gaia stop && gaia start`</Info>
