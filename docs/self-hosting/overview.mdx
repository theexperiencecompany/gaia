  **Which guide is for me?** This tab is for running your own GAIA with the `gaia` CLI. Using GAIA Cloud or an instance someone else runs? See the [Docs](/introduction). Changing GAIA's code? See [Developers](/developers/introduction).

Run GAIA on your own machine with two commands, then finish setup in your browser.

```bash
curl -fsSL https://heygaia.io/install.sh | sh
gaia up
```

Open http://localhost:3000/setup, create the admin account and paste an API key for any supported AI provider (or point GAIA at a local Ollama). No cloud accounts and no hand-edited files.

New here? The [walkthrough](/self-hosting/walkthrough) shows every step with screenshots. Prefer a hosting platform? See [Deploy options](/self-hosting/one-click-deploy).

## What you need

- **Docker.** If it's missing, `gaia up` offers to install it.
- **8 GB RAM**, 2+ CPU cores and 10 GB of disk. It boots in less, but the local memory model needs the RAM later ([details](/self-hosting/maintenance#memory-sizing)).
- **One AI provider**: a key from OpenAI, OpenRouter or Google Gemini, any OpenAI-compatible gateway, or [Ollama](https://ollama.com) running locally with no key. See [AI models and tools](/self-hosting/ai-models-and-tools).

## Everyday commands

| To | Run |
| --- | --- |
| Update | `gaia update` |
| Find problems | `gaia doctor` |
| Back up | `gaia backup` |
| Restore | `gaia restore --from backups` |

Updating never touches your chats or settings. All data lives in Docker volumes. More in [Updates & backups](/self-hosting/maintenance).

## Self-host vs Cloud

Self-hosted GAIA runs the same code as GAIA Cloud, with a lighter setup.

| Area | GAIA Cloud | Self-host |
| --- | --- | --- |
| **Sign-in** | Google sign-in through WorkOS | Email and password. The first account is the admin. Others join by invite link (**Settings → Members**) |
| **Billing** | Plans and limits | None. Everyone gets every feature |
| **Support** | GAIA's support team | Nothing is sent to GAIA. The form links to [GitHub issues](https://github.com/theexperiencecompany/gaia/issues) and [discussions](https://github.com/theexperiencecompany/gaia/discussions) |
| **AI and tools** | Managed keys | Your own, in **Settings → Providers & Tools** |
| **Files** | Cloudinary and R2 | Docker volumes on your server. See [File storage](/self-hosting/ai-models-and-tools#file-storage) |
| **Running code** | E2B | Off until you add an E2B key or turn on the local sandbox. See [Running code](/self-hosting/ai-models-and-tools#running-code) |
| **Voice, browser automation** | Available | Not available. See [what's missing](/self-hosting/ai-models-and-tools#not-available-on-self-host) |
| **Logs** | Loki and Grafana | Container logs, 10 MB x 3 rotated files per service |
| **Updates and backups** | Managed | You run `gaia update` and `gaia backup` |

<Accordion title="How it is configured">
  Self-host runs with `ENV=selfhost` and `AUTH_MODE=local`. Cloud and development use `AUTH_MODE=workos`.

  Only the database addresses (Compose provides them) and three machine secrets are needed: `AGENT_SECRET`, `BOT_SESSION_TOKEN_SECRET` and `EMAIL_UNSUBSCRIBE_SECRET`. `gaia up` generates them. Infisical is never contacted, even if old credentials are in the environment.

  `INSTANCE_SECRET` signs sessions and encrypts the keys you save. `gaia up` writes it to `.env` on a fresh install, so the key lives apart from the database. Without it, GAIA generates one on first boot and stores it in the database next to the keys, so a database dump alone can read them. See [the instance secret](/self-hosting/maintenance#the-instance-secret).
</Accordion>

<Accordion title="What runs on your machine">
  Everything runs as Docker containers. Only the proxy opens a port (http://localhost:3000), so GAIA works on any hostname or IP with no URL setup.

  | Component | What it is |
  | --- | --- |
  | Proxy | Caddy, the single entrypoint |
  | Web | Next.js app, served at `/` |
  | Backend | FastAPI plus a background worker, served at `/api/v1` |
  | Databases | PostgreSQL, MongoDB, Redis, ChromaDB, RabbitMQ |
  | Files | Docker volumes for uploads and each user's workspace |
</Accordion>
